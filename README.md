## 1. 项目目标与范围

### 1.1 目标

采集全校各微信公众号发布的**讲座（含讲座单）**、**文体活动**（晚会/歌手大赛/展览等）、**志愿招募**三类信息，聚合到一个网页上，按时间排序、分类筛选、支持搜索。

### 1.2 非目标（明确不做什么）

- 不爬取非公众号来源的信息（如学校官网、论坛）
- 不做自然语言问答/对话
- 不做用户系统/权限管理
- 不做 App，仅 Web 页面

### 1.3 用户场景

| 角色 | 痛点 | 使用方式 |
|------|------|----------|
| 普通学生 | 关注十多个公众号，经常漏掉讲座/活动 | 打开网页按日期浏览 |
| 需讲座单的学生 | 不知道哪个讲座发单 | 筛选"有讲座单"的条目 |
| 志愿者 | 志愿招募分散在各公众号 | 查看"志愿招募"tab |

## 2. 调研结果：现有开源项目

### 2.1 数据采集相关

#### 方案 A：wechatDownload (qiye45) — ⭐ 首选

| 项目 | 说明 |
|------|------|
| 地址 | https://github.com/qiye45/wechatDownload |
| Stars | 8,700+ |
| 状态 | **活跃维护**，2026 年 6 月刚更新 v4.6 |
| 原理 | 通过微信桌面版捕获认证 token，调用微信官方 API 下载文章 |
| 输出格式 | HTML / MHTML / Markdown / PDF / DOCX / CSV |
| 核心功能 | 批量下载历史文章、评论、合集、支持 MCP 协议调用 |
| 系统要求 | Windows / Mac，需安装微信桌面版 |

**关键优势**：
- 不走网页爬虫（不会被反爬封 IP）
- 不走搜狗搜索（已死）
- 走的是微信官方 API，稳定可靠
- MCP 支持意味着可以被脚本/程序自动化调用

#### 方案 B：wechat-mp-rpa-links (qingchunshiqu)

| Stars | 较新项目 |
| 状态 | 2026 年 6 月创建，活跃 |
| 原理 | Playwright 模拟浏览器登录微信公众号后台（mp.weixin.qq.com），搜索目标公众号拉取文章列表 |
| 要求 | 需要一个微信公众号的登录账号 |

### 2.2 内容提取（LLM）相关

本项目需要从文章正文中提取结构化活动信息，这一环节没有现成的开源项目可以直接使用，需要自己构建：

- 使用 LLM API（DeepSeek / 通义千问 / GPT-4o mini）
- 输入：文章标题 + 正文
- 输出：结构化 JSON（分类、时间、地点、是否有讲座单等）
- 成本估算：DeepSeek API 约 0.5 元/百万 token，一篇文章 ~2000 token，一天 50 篇约 0.05 元

### 2.3 前端展示相关

没有找到专门针对"校园活动聚合"的成熟项目，但可以参考：

- 事件日历类 UI：FullCalendar.js、React Big Calendar
- 卡片列表类 UI：各类活动/票务网站的首页设计模式

## 4. 推荐架构（详细）

```
┌─────────────────────────────────────────────────────────────────┐
│                     轻薄本 (Windows，每天开机)                    │
│                                                                  │
│  ┌──────────────────────┐    ┌──────────────────────────────┐   │
│  │  wechatDownload v4.6  │    │  Python 解析流水线            │   │
│  │  (带 MCP 接口)        │───▶│                              │   │
│  │                      │    │  1. 读取新导出的 CSV/文章      │   │
│  │  定时任务 (Task Scheduler)  │  2. 去重 (比对文章URL)      │   │
│  │  每 4-6 小时自动拉取   │    │  3. 调用 LLM API 提取结构化  │   │
│  │  所有公众号新文章      │    │  4. 写入本地 SQLite          │   │
│  │                      │    │                              │   │
│  │  输出: CSV / Markdown │    │  5. 推送到 GitHub (数据文件)  │   │
│  └──────────────────────┘    └──────────┬───────────────────┘   │
│                                         │                       │
└─────────────────────────────────────────┼───────────────────────┘
                                          │ git push (JSON 数据文件)
                                          ▼
┌─────────────────────────────────────────────────────────────────┐
│               GitHub + Vercel (全免费)                          │
│                                                                  │
│  GitHub Repository:                                              │
│    ├── data/events.json         ← 推送的数据文件                │
│    ├── index.html               ← 前端页面                      │
│    ├── style.css                                                 │
│    └── app.js                                                    │
│                                                                  │
│  Vercel / GitHub Pages: 自动部署静态站点                        │
│    → 24h 在线，任何人都能打开                                   │
│    → 前端 JS 从 data/events.json 读取数据                       │
└─────────────────────────────────────────────────────────────────┘
```

### 4.1 为什么选择这个架构

| 决策 | 理由 |
|------|------|
| 轻薄本做采集 | 你已有的设备，零额外成本；wechatDownload 需要在 Windows 上运行 |
| 不直接暴露本机服务 | 本机开关机不可控，用 GitHub + Vercel 实现 24h 在线 |
| Vercel 托管前端 | 免费、自动 HTTPS、全球 CDN |
| GitHub 做数据中转 | 免费、有版本历史、可回滚 |
| SQLite 本地存储 | 零配置、单文件、适合本地场景 |
| LLM API 做解析 | 比正则/规则引擎准确得多，能处理各种文章格式 |

### 4.2 流程图（每日工作流）

```
早上 8:00 开机
  → Windows Task Scheduler 触发采集脚本
  → wechatDownload (MCP) 检查所有公众号的新文章
  → Python 解析流水线处理新文章
    → 去重 → LLM 提取 → 写入 SQLite
  → 生成 data/events.json
  → git push 到 GitHub
  → Vercel 自动重新部署（或前端直接从 JSON 文件读取）

用户打开网页
  → 看到最新的讲座/活动/志愿信息
  → 可筛选、搜索、点击查看详情
```

## 5. 关键组件详解

### 5.1 数据采集 (wechatDownload)

**初始设置（一次性工作）**：

1. 下载安装 wechatDownload（GitHub Releases）
2. 微信桌面版保持登录状态
3. 对于每个目标公众号，找到一篇文章，复制链接
4. 在 wechatDownload 中点击"获取公众号 ID"，粘贴链接
5. 软件自动复制另一段链接，发到文件传输助手，用微信内置浏览器打开
6. 等待自动获取密钥，该公众号注册完成

**预期采集的公众号类型**（10-30 个）：

| 类别 | 示例 |
|------|------|
| 校级学生组织 | XX大学学生会、XX大学研究生会 |
| 各学院学生会 | XX学院学生会、XX学院团总支 |
| 志愿者组织 | XX大学青年志愿者协会 |
| 艺术/文体 | XX大学艺术团、XX大学社团联合会 |
| 图书馆/讲座 | XX大学图书馆、XX大学学术文化部 |
| 就业/创业 | XX大学就业指导中心 |

**定时采集方案**：

每次拉取前几页的新文章（wechatDownload 支持自定义页数范围），导出 CSV 格式到固定目录。

### 5.2 内容解析 (Python + LLM)

**输入**：文章标题 + 正文（从 CSV 或 Markdown 文件读取）

**LLM Prompt 设计**：

```
请从以下微信公众号文章中提取活动信息。
输出 JSON 格式，包含以下字段：
- category: "lecture" | "event" | "volunteer" | "other"
- title: 活动名称
- organizer: 主办方（公众号名称）
- date: 日期 (YYYY-MM-DD)
- start_time: 开始时间 (HH:mm)
- end_time: 结束时间 (HH:mm)
- location: 地点
- has_ticket: true/false (仅讲座，是否发讲座单)
- ticket_info: 讲座单相关说明
- volunteer_hours: 志愿时长（仅志愿招募）
- recruit_deadline: 报名截止日期
- description: 活动简介（50字以内）
- source_name: 来源公众号
- source_url: 原文链接

文章标题：{title}
文章正文：{content}
```

**分类规则补充**（LLM 判断不准时的 fallback）：

| 关键词 | 分类 |
|--------|------|
| 讲座、报告、论坛、学术、讲座单 | lecture |
| 大赛、晚会、演出、展览、歌手、表演 | event |
| 志愿者、招募、义工、志愿时长 | volunteer |

**去重逻辑**：
- 以 `source_url`（文章链接）为唯一标识
- 已存在的文章跳过
- 同一活动在不同公众号发布 → 保留最早的来源，在页面标注"多个来源"

### 5.3 存储层 (SQLite)

```sql
CREATE TABLE articles (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_url TEXT UNIQUE NOT NULL,
  source_name TEXT NOT NULL,
  title TEXT NOT NULL,
  content TEXT,
  publish_date DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  article_id INTEGER NOT NULL,
  category TEXT NOT NULL,  -- lecture | event | volunteer
  title TEXT NOT NULL,
  organizer TEXT,
  date TEXT,
  start_time TEXT,
  end_time TEXT,
  location TEXT,
  has_ticket INTEGER DEFAULT 0,
  ticket_info TEXT,
  volunteer_hours REAL,
  recruit_deadline TEXT,
  description TEXT,
  source_name TEXT NOT NULL,
  source_url TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (article_id) REFERENCES articles(id)
);
```

## 6. 项目经理质疑与风险评估

> 以下是以项目经理视角对方案提出的质疑、风险识别和改进建议。

### 质疑 1：wechatDownload 认证需要手动操作，无法全自动

**问题**：wechatDownload 获取密钥后，token 会在几小时后过期，需要重新在微信中打开链接。这意味着"每 4 小时自动拉取"做不到完全无人值守。

**影响等级**：🔴 高

**应对措施**：
- 接受"半自动"模式：每天早上开机后手动认证一次，当天后续采集可用
- 或测试 wechatDownload 的 token 有效期，如果实际能撑 12-24 小时则只需每天认证一次
- 长期方案：如果发现频率不够，可以切换到方案 B（wechat-mp-rpa-links）配合 Playwright 复用登录态

### 质疑 2：学校公众号的文章格式多样，LLM 提取准确率不是 100%

**问题**：
- 有些推文同时包含多条活动信息（如"本周活动预告"一次列 5 个活动）
- 有些活动不写具体时间，只写"待定"
- 有些文章的"讲座"实际上不发讲座单

**影响等级**：🟡 中

**应对措施**：
- Prompt 中要求 LLM 提取**多个活动**（支持一篇文章解析出多条活动记录）
- 对不确定的字段置为 null，前端显示"待定"
- 设计一个反馈机制：用户可以标记错误信息（简单 button，记录到 GitHub Issue）
- 初期人工抽查，逐步优化 prompt

### 质疑 3：轻薄本不是 24h 开机，数据有延迟

**问题**：你每天不一定全天开机，有时可能晚上才开。

**影响等级**：🟡 中

**应对措施**：
- 数据更新频率为"每次开机时更新"，前端页面显示"数据更新于 X 分钟前"
- 如果某天没开机，数据就是昨天的快照，但大部分活动提前几天发布，影响不大
- 如果后期发现延迟不可接受，可买最便宜云服务器（学生机 10 元/月）作为中转

### 质疑 4：微信封号/封 API 的风险

**问题**：高频采集可能导致微信账号被限制。

**影响等级**：🟡 中

**应对措施**：
- wechatDownload 走的是微信桌面版 API，而非网页爬虫，风险相对可控
- 控制采集频率：不要超过 60 次/分钟（wechatDownload 已有间隔设置）
- 使用**独立的微信小号**进行采集，不影响主号
- 如果严重到被封，可以用朋友/同学的微信切换

### 质疑 5：Vercel 免费版限制

**问题**：Vercel 免费版有每月带宽和构建次数限制。

**影响等级**：🟢 低

**应对措施**：
- 纯静态页面，不涉及后端，几乎没有带宽消耗
- 如果使用 GitHub Pages 则完全无限制
- 前端直接从 GitHub raw 或 jsDelivr CDN 读取 JSON，不需要构建

### 质疑 6：仅本机采集，哪天电脑坏了怎么办？

**问题**：轻薄本重装系统、更换电脑、硬盘损坏等情况。

**影响等级**：🟢 低

**应对措施**：
- SQLite 数据库和配置文件可通过 git 同步备份
- wechatDownload 的公众号配置可导出
- 更换电脑后只需重新安装软件 + 恢复配置
- 密钥需要重新获取，但这是一个一次性的操作（对每个公众号）

### 质疑 7：LLM API 费用

**问题**：长期使用 LLM API 需要持续付费。

**影响等级**：🟢 低

**应对措施**：
- 成本估算：DeepSeek API 约 0.5 元/百万 token
- 每篇文章 ~2000 token，假设每天 30 篇新文章
- 日费用：30 × 2000 / 1000000 × 0.5 = 0.03 元
- 月费用不到 1 元
- 通义千问还有免费额度

### 质疑 8：没有"实时更新"，只有"定时更新"

**问题**：用户期望实时看到新活动，但实际上只有每次采集时才更新。

**影响等级**：🟢 低

**应对措施**：
- 页面展示"数据更新于 X 分钟前"的提示
- 微信公众号本身也没有实时通知，读者看到文章时已经滞后
- 如果需求强烈，可以加一个"手动刷新"按钮，触发增量拉取

### 风险矩阵总结

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| token 过期需手动重认证 | 高 | 中 | 每天认证一次 + 评估是否走方案 B |
| LLM 提取不准确 | 中 | 中 | 支持多条目提取 + 人工抽查 + 用户反馈 |
| 微信封号 | 低 | 高 | 用小号 + 控频 |

## 7. 备选方案（如果方案 A 走不通）

### 方案 B：wechat-mp-rpa-links（需要公众号账号）

如果你或同学能借到一个微信公众号（学生组织/社团的），可以走这个方案：

```
服务器 (云服务器或本机):
  Playwright → 登录 mp.weixin.qq.com
  → 搜索目标公众号 → 获取文章列表
  → LLM 解析 → SQLite → API → 前端
```

**优点**：完全不依赖微信桌面版，可在服务器 24h 运行
**缺点**：需要公众号账号 + 需要处理公众号后台的反爬和验证码

### 方案 C：纯手动 + 半自动（最低成本验证）

```
你每天手动：
  1. 打开各公众号 → 复制新文章链接
  2. 粘贴到 wechatDownload → 下载
  3. 运行 Python 脚本解析 → 查看网页

自动化程度：30%
```

**适用场景**：先用这个方案跑 1-2 周，验证 LLM 提取效果和用户需求，再决定是否投入自动化。
