# 微信数据采集：逆向调研结论

> 本文档记录对「微信全自动采集」的技术攻坚过程与结论，供后续继续研究参考。

## 一、目标

从天大 27+ 个微信公众号自动采集文章，提取活动信息，避免逐个公众号手动下载。

## 二、已完成的突破

### 2.1 密钥机制（已完全搞懂）

微信桌面版（4.0 / xwechat）会把会话密钥**明文**写进本地数据目录：

```
C:\Users\<用户>\AppData\Roaming\Tencent\xwechat\radium\web\profiles\
  └─ multitab_<hash>\
       ├─ History.wxbak       # 含 pass_ticket
       ├─ Share Data          # 含 key/pass_ticket/uin
       ├─ shared_proto_db\*.log  # 含 key/uin
       └─ Cache\Cache_Data\data_*  # 最新密钥
```

关键参数（都在含 `pass_ticket` 的 URL 里，明文）：
- `uin`：用户 ID，**base64 编码**（如 `NzQ2MzY2Nzg5` → `746366789`）
- `key`：会话密钥（长 hex）
- `pass_ticket`：会话票据

### 2.2 提取脚本（已实现）

`parser/wechat_key.py`：扫描微信数据目录，按文件修改时间取最新，正则提取 uin/key/pass_ticket。

### 2.3 接口结构（已完全搞懂）

文章列表接口 `getmsg`：

```
https://mp.weixin.qq.com/mp/profile_ext?action=getmsg
  &__biz={公众号ID}&f=json&offset={页码}&count=10&is_ok=1&scene=124&uin={uin}
```

返回 JSON，`general_msg_list` 里有文章标题和链接。

## 三、卡点（未攻克）

`getmsg` 接口直接调用返回 `ret: -3, errmsg: "no session"`。

原因：仅凭 `uin`/`key`/`pass_ticket` 不够，还需要两个会话 cookie：
1. **`wxtokenkey`**：由工具代码里一段 `hashlib` 哈希算法计算得出
2. **`poc_token`**：通过 `action=home` 请求的 Set-Cookie（`poc_sid`）二次请求获得

且 `action=home` 直接请求会返回「验证」防爬页。

### 3.1 为什么卡住

- 工具（wechatDownload）用**改版 PyInstaller** 打包，magic cookie 被改，`pyinstxtractor` 反编译失败，拿不到 `wxtokenkey` 的确切哈希算法。
- 工具 MCP 的 `batch_download_articles` 只能下「当前选中」的公众号，`get_public_account_id(url)` 的 url 参数被忽略，无法程序化切换账号。

## 四、结论与建议

| 方案 | 状态 |
|------|------|
| 完全自动化（一密钥遍历全部账号） | ❌ 差 wxtokenkey/poc_token 算法 |
| 密钥全局共享（一个密钥管所有号） | ✅ 已验证 |
| 密钥从本地明文提取（免手动"获取密钥"） | ✅ 已验证 |

**本质限制**：微信密钥周期性过期 + 需要微信桌面保持登录，任何方案都无法做到「一年无人值守」。

**建议的现实方案**：wechatDownload（自动处理防爬）逐个账号下载 + `autopilot.py` 自动解析推送，唯一手动是微信密钥过期时点一下。

## 五、后续可尝试的方向

1. **动态调试**：py-spy / gdb 附加到 wechatDownload 进程（PID 见任务管理器），在 hashlib 调用处断点，观察 `wxtokenkey` 的哈希输入。
2. **网络抓包**：给 wechatDownload 配置本地代理，捕获其 `action=home` 请求里的 `wxtokenkey` 值，反推哈希输入。
3. **微信读书（WeRead）API**：wewe-rss 项目（已归档）走的路线，WeRead 登录态更持久，可能更适合多账号监控。
4. **改版 PyInstaller 逆向**：定位并恢复被改的 magic cookie，用 pyinstxtractor 提取 .pyc 反编译。
