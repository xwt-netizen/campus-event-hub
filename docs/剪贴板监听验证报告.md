## 回答五个问题

### 1. 剪贴板监听能否被外部 Python 触发

**能。** 用普通 Windows 剪贴板 API（`Set-Clipboard` / `win32clipboard`）写入含 `__biz` 的公众号 URL 即可触发。工具会自动：

- 检测剪贴板变化（`QApplication.clipboard().dataChanged`）
- 提取 `__biz`，更新 `self.business_id`
- **自动将剪贴板改写为确认链接**（如 `...action=home&__biz=XXX&scene=124#wechat_redirect`），证明工具确实处理了 URL

### 2. business_id 是否发生变化

**是，可程序化切换。** 实测两次成功：

```
空 → 北洋军乐团 (MjM5NjI1NjM5Mg==)  ✅
北洋军乐团 → 天津大学 (MjM5NzkwNzU0Mg==)  ✅
```

### 3. MCP batch_download_articles() 是否随之切换公众号

**读取的是切换后的 business_id，逻辑上会跟随。** 但受「获取密钥」流程约束：

- 切换到一个**新公众号**后，工具自动触发「获取密钥」流程（日志出现 `开始获取密钥...`）
- 该流程可能需要**在微信打开确认链接**才能完成
- 若密钥未确认，batch 下载不开始（日志无「开始下载」记录），business_id 状态可能短暂不稳定

### 4. 最小可行自动化流程

```python
for url in 公众号URL列表:          # 每个号一篇已知文章链接
    set_clipboard(url)            # 写入剪贴板（含 __biz）
    sleep(3)                      # 等工具处理
    # 可选：检查剪贴板被改写为 confirmation URL 以确认处理完成
    mcp.batch_download_articles() # 批量下载当前 business_id
    wait_download_done()
```

**关键前提**：切换后的公众号密钥需已获取（或首次时微信人工确认一次）。密钥全局共享，已获取过的公众号切换后可直接下载。

### 5. 失败原因 / 限制

- **受密钥确认流程阻塞**：切换新公众号触发「获取密钥」，需微信确认；未确认前 batch 不下载，状态不稳定
- 其他公众号切换（密钥已有效时）应正常，但本次实验受天津大学密钥未确认影响，未能 100% 复现连续切换+下载

## 结论

**剪贴板监听是可行的程序化切换突破口，`business_id` 可自动更新。** 半自动方案可升级为：

```
外部 Python 依次写剪贴板公众号 URL → 工具自动切换 business_id
  → 调 MCP batch_download_articles() 下载
  → 仅首次/密钥过期时需微信人工确认
```

相比纯手动「切换+获取ID+批量下载」，压缩为「写剪贴板 + 调 MCP」，人工只负责密钥确认。
